Xenon's recommender reads a traveller's request, searches the package database, checks the forecast for the travel date, and explains its top pick. Ask it in English or Arabic, then follow up.

Add a test trip

Make up a trip and the advisor runs your last search again with it included, so you can see where it ranks and why. It stays in this tab and disappears when you refresh.

How this demo works

This runs the recommender's own code in your browser: the scope checks, the request parser, the scoring, and the replies are the same files as the Node.js service, and only the MongoDB database is swapped for the project's 10 demo packages plus any test trips you add. The live service can also have Qwen3 read requests through Ollama; this demo uses its built-in parser, which understands English and Arabic. Forecasts come from Open-Meteo and exchange rates from Frankfurter when your browser can reach them. Replies are in English, as in the service.

Distributed e-voting system

Distributed Systems course project

An online voting platform built to stay correct under load. Voters cast one ballot per election, admins run elections, and auditors check the results. Two API servers sit behind a load balancer, and votes go through a queue to a worker that writes them to the database.

e-voting /login

Sign-in for voters (national ID and password, optional 2FA) and admins.

How it stays correct
  • Each vote becomes a queue job keyed to the voter and election, so a double-click or retry can't create a second job.
  • A Redis lock turns away duplicate requests while a vote is being processed.
  • A unique database index on voter and election is the final guard against double voting.
  • Votes are hash-chained so auditors can check nothing was changed afterwards.

MySchoolDB

ProTech internship · query it here

The school database I built on my own during my ProTech internship. It covers students, parents, teachers, classes, courses, grades, and addresses across Jordan's 12 governorates. It has 11 tables, a stored procedure for every table, triggers that enforce the school's rules, views and functions for rankings, JSON and XML import, an audit trail, a nightly maintenance job, and 7 SSRS reports.

The database loads when you scroll here.

This is a SQLite copy of the same tables, rules, and sample data, running in your browser. The original is T-SQL on SQL Server, where each table is used through a stored procedure. Change whatever you like; Reset puts it back.

What the database enforces
  • A class can't go over its capacity, and a grade's course level has to match the student's class level. Both are triggers.
  • A subject can't be taught below its minimum level, and every mark has to be between 0 and 100.
  • Every grade change is written to an audit table with the old value, the new value, and who made it.
  • Every stored procedure call is logged, so failed saves, imports and deletes leave a record with the reason.

Next projectSalary prediction

Salary prediction

Team project · Data Science course · try the model

A machine-learning model that estimates a yearly salary from someone's job, industry, country, education, age, and experience. It learns from 28,090 answers to an open salary survey, typed by hand into free-text boxes, so most of the work was cleaning: 22,832 usable records were left at the end.

Estimated salary …

The model runs in your browser: 40 decision trees exported from scikit-learn, each giving its own estimate. The figure above is their average and the range is the middle half of their answers. On people it never saw, it is off by about $22,000 on average (R² 0.43), so treat it as a rough guide, not a quote. Salaries are in US dollars at the exchange rates used in the project.

From survey answers to a model
  1. Merged the currency columns and converted every salary to US dollars, after mapping spellings like "American Dollars" and "Polish Złoty" to currency codes.
  2. Grouped more than 14,000 different job titles into 31 job families with keyword rules, then fuzzy matching, then the person's industry as a fallback.
  3. Fixed country names typed many ways ("usa", "U.S.", "United States of America") with fuzzy matching against a country list.
  4. Turned age and experience ranges into numbers, fixed answers with more experience than age, and removed salary outliers with the IQR and z-score methods.
  5. Trained a Random Forest and checked it on a 20% test set it never saw.
What matters most to the model

Industry, years in the field, country, education, and job drive most of the estimate. This web version leaves out gender and race, which the original model also used. Without them the test score drops by only 0.02.
